1. Create the skill folder

Inside your project, create:

your-project/
└── .agents/
    └── skills/
        └── concise-code/
            └── SKILL.md

You can create it from PowerShell:

mkdir .agents\skills\concise-code
notepad .agents\skills\concise-code\SKILL.md



2. Make the skill stronger for Antigravity

---
name: concise-code
description: Enforce concise, minimal, readable, and non-overengineered code during implementation, debugging, and refactoring. Prefer the smallest correct solution and existing project patterns. Avoid unnecessary abstractions, files, helpers, wrappers, comments, dependencies, and unrelated changes.
---

# Concise Code

Write the simplest correct solution.

## Rules

- Use the minimum code necessary.
- Inspect existing code before creating anything new.
- Reuse existing components, functions, utilities, hooks, types, APIs, and patterns.
- Prefer modifying existing code over creating new code.
- Do not create unnecessary files.
- Do not create one-use helper functions.
- Do not create one-use components unless they improve clarity or maintainability.
- Do not add unnecessary classes, services, factories, wrappers, interfaces, enums, or abstraction layers.
- Do not duplicate existing functionality.
- Do not add unnecessary comments.
- Do not add unnecessary dependencies.
- Do not refactor unrelated code.
- Do not change working architecture without a requirement.
- Do not optimize prematurely.
- Do not sacrifice readability merely to reduce line count.

## Before Implementation

Check:

1. Does this already exist?
2. Can the existing code be modified?
3. Can an existing component/util/function be reused?
4. Can the task be solved with a smaller change?
5. Am I introducing an abstraction that is only used once?
6. Am I touching unrelated files?

Prefer:

existing code + smallest necessary change

over:

new abstraction + new files + unnecessary architecture.

## UI

- Reuse existing UI components.
- Reuse existing design tokens.
- Avoid unnecessary wrappers.
- Avoid duplicate components.
- Keep responsive implementations simple.

## Backend/API

- Reuse existing services and utilities.
- Do not create duplicate endpoints.
- Do not change API contracts unless explicitly requested.
- Do not change database schema unless explicitly requested.

## Refactoring

Only refactor code required for the task.

Do not rewrite working code just because another style is preferred.

## Security

Never remove security, authentication, authorization, validation, or error handling just to reduce code.

## Final Check

Before finishing:

- Can this be simpler?
- Did I create anything unnecessary?
- Did I duplicate existing code?
- Did I create an unnecessary abstraction?
- Did I modify unrelated files?
- Is the code still readable and maintainable?

If unnecessary complexity exists, simplify it.

## Principle

**Minimum necessary code. Maximum necessary clarity.**

Prefer:

simple + correct + readable + maintainable

over:

short + clever + fragile.

your-project/

    └── concise-code/
        └── SKILL.md

The important part is the exact filename:

SKILL.md

Not:

skill.md
concise-code.md
SKILL.txt


4. How you use it

The nice thing about an Antigravity skill is that you generally don't need to paste the entire instructions into every prompt.

Because the skill description tells the agent when it is relevant, Antigravity can use it when you're doing coding/implementation work.

For example, instead of:

Build the login page and make the code concise.

You can simply say:

Implement the login page according to the existing project architecture.

The skill should guide the implementation toward:

existing code
      ↓
smallest required change
      ↓
no unnecessary abstraction
      ↓
no unrelated refactoring



5. You can explicitly tell Antigravity to use it

If you want to be certain, say:

Use the concise-code skill for this task.

Implement only what is required.
Inspect existing code first.
Reuse existing components and utilities.
Do not create unnecessary files, abstractions, helpers, wrappers, or dependencies.
Do not modify unrelated code.

8. One more skill I'd recommend

Your concise-code skill solves:

"Don't write 100 lines when 20 are enough."

But you also have another problem with AI coding:

"Don't change things I didn't ask you to change."

So I'd create a second skill:

.agents/
└── skills/
    ├── concise-code/
    │   └── SKILL.md
    │
    └── minimal-change/
        └── SKILL.md

The second one would enforce:

ONLY change what is necessary.

DO NOT:
- change database schema
- change APIs
- rewrite working components
- change unrelated UI
- rename unrelated variables
- change dependencies unnecessarily
- refactor unrelated code
- modify configuration unnecessarily

This combination is much stronger:

        Antigravity
             │
       ┌─────┴─────┐
       ▼           ▼
Concise Code   Minimal Change
       │           │
       └─────┬─────┘
             ▼
     Small + Safe Changes
